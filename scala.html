The Scala implementations: which is which

For a new program in Scala 3, use okay-scala. If the code must also compile on Scala 2.13, or it uses the libraries written over the common interface (okay-http, okay-mcp, okay-faces, okay-store), use okay-simple; its adapter runs the same code on okay-scala's machine. The other repositories are the platform and its kernel, a direct-style library for Java with Scala front ends, a reference model in three languages, and the experiments that came before them.

The state of the master branches on 11 November 2026. Every statement on this page was checked in the repositories; where a file says it, the file is named. Outside Scala: effects in other languages.

The implementations

Eleven repositories hold an implementation of effects in Scala. Seven are public. Three of them are released: okay-scala, okay-simple and okay-direct.

One name means three things. okay-effects is the organization. It is also the name of okay-simple's artifacts and package (okay-effects, okay-effects-machine, okay.effects). And it is the repository of the reference model, whose Scala package is okay.effects.scala. On this page "okay-effects" is the repository.

A program in each

Copied from each repository's own documentation.

okay-scala (README.md)

import okay.scala3.*       // the rows, programs, handlers, the machine
import okay.scala3.std.*   // the standard effects: State, Reader, Writer, Fail, Async, ...

def greet[R[_]: Has[Reader % String] : Has[State % Int] : Has[Writer % String]]: Int ! R =
  for
    name <- Reader.ask
    n    <- State.get
    _    <- State.put(n + 1)
    _    <- Writer.tell(s"hello, $name")
  yield n

type Greeting[X] = (Reader % String + State % Int + Writer % String)[X]

run(State.run(12)(Reader.run("Ann")(Writer.run(greet[Greeting]))))   // (13, (List(hello, Ann), 12))

okay-simple, Scala 3 (docs/getting-started.md)

import okay.effects.*
import okay.effects.std.*

/** greets, in any row that has a `Reader` of the name and a `State` of the count */
def greet[R[_]: {Has[Reader % String], Has[State % Int]}]: String ! R =
  for
    name <- ask[String, R]
    n    <- get[Int, R]
    _    <- put[Int, R](n + 1)
  yield s"hello, $name (#${n + 1})"

type App = Reader % String + State % Int

val handled: (Int, String) ! Pure = state(0)(reader("Ann")(greet[App]))
val result: (Int, String) = run(handled)

In Scala 2.13 the same program takes its evidence as implicits, and a row is written with names: ((Reader % String) + (State % Int))#L.

okay-effects, the Scala kernel (README.md)

import okay.effects.scala.*, std.*

val p: Int ! State % Int + Choose =
  for x <- Choose.among(1, 2); s <- State.get[Int]; _ <- State.put(s + x) yield s + x

run(Choose.all(State.run(0)(p)))   // List((1, 1), (2, 2))
run(State.run(0)(Choose.all(p)))   // (3, List(1, 3))

okay-direct, the Scala 3 front end (docs/scala.md)

import okay.direct.{Effect, Effects}
import okay.direct.scala3.*

def program(heads: Boolean)(using Effect[Reader[Int]], Effect[State[Int]], Effect[Fail[String]]): Int =
  val base = Reader.ask[Int]
  State.put(State.get[Int] + 1)
  val result = if heads then base else -base
  if result < 0 then Fail.raise(s"negative: $result") else result

given Effects = LoomEffects()
Reader.run(42)(State.run(0)(Fail.attempt(program(true))))     // (1, Right(42))

okay-core (README.md)

import okay.*

def greet: Int ! Reader % String + Writer % String =                  // a program as its type says it
  ask[String].flatMap(name => tell(s"hello, $name").map(_ => name.length))

run(reader("Ann")(writer[String, Int, Reader % String +: Pure](greet)))   // (List("hello, Ann"), 3)

Are they compatible?

In notation, mostly. In classes, no: each library has its own, and a program of one runs on another only through an adapter. In behaviour, as far as two shared test suites reach. On the wire, one of them.

Notation

okay-simple, okay-scala and the Scala kernel of okay-effects write a program the same way. A ! R is a program of the value A over the row R. A row is a type constructor: R + E is [X] =>> Sum[R, E, X], F % S is the effect F with its parameter, Pure is the empty row. In[E, R] and Has[E] say that an effect is in a row, Split[E, R, Rest] is what a handler takes, Sub[R, S] puts a program into a bigger row. All three define these names.

They are three sets of classes. Sum, Void and the program type are defined in each library, in okay.effects, okay.scala3 and okay.effects.scala. A program of one is not a program of another, and a handler of one does not take a program of another.

The words differ. In okay-simple an operation is a function that names its row, get[Int, R], and a handler is state(0). In okay-scala and in okay-effects an operation is a word of its effect's object, State.get, and a handler is State.run(0). okay-scala names two effects Fail and Yield; okay-effects names them Throws and Emit and has the other two names as aliases.

okay-core and okay use the same three symbols, A ! E1 + E2 and F % S, over a different row: a type, E +: T ending in Pure, with a typed path to each effect.

okay-direct has no row and no monad. A program is plain code that takes a capability for each effect, using Effect[State[Int]]; a body with no handler for an effect does not compile.

Every adapter starts from okay-simple's interface. None runs a program of okay-scala, okay-direct or okay-effects on another implementation.

Behaviour

Two test suites are shared between repositories. Neither covers all of them.

The family's TCK is in okay-kernel (tck/Tck.scala): a thousand random programs, their outcomes folded into one number, -8623788747993822161. These come to that number: okay-kernel's reference machine, okay-core through OnCore, okay-java (run from okay-kernel's integration tests), the machine crate of okay-rust, the machine of okay-zig, and each of the three kernels of okay-effects. okay-effects compares with the constant; the reference machine is not in that repository (its README says so). okay-simple, okay-scala and okay-direct do not run this TCK. The okay platform does not run it itself; it runs on okay-core, which does.

okay-simple's interface suite (InterfaceSuite, the artifact okay-effects-tck) runs on the machine, on Free, on tagless over both, on okay-scala's machine through OnCek, on okay-core through Core, and on okay-kernel's reference machine through OnKernel. On okay-direct it runs through OnDirect; on Loom and on threads the tests that resume a continuation twice are refused.

So okay-scala and okay-effects are not held to one test: okay-scala is not checked by the digest, and okay-effects is not checked by the interface suite.

The wire

The okay wire is the protocol of the okay platform: a program runs in one process and its operations are answered in another. Of the other repositories on this page only okay-effects speaks it, in all three languages. It implements a part: its wire/README.md lists what is left out (tables and data frames, TCP and TLS among them). Its hosts and workers are checked with each other and against transcripts; a script, wire/family/check.sh, runs its host with the far sides of okay-zig, okay-lean, okay-ts and okay's Python shim, and okay's own host with its three workers, where those repositories are at hand. okay-simple, okay-scala, okay-direct and okay-core have no implementation of the wire.

okay-scala and the reference kernel

The two closest: the same notation, a machine of frames and levels in both, the same five handler shapes. okay-scala as released in 0.1.1; okay-effects' Scala kernel as on its master.

How they came about

Dates are those of the commits and tags in each repository.

WhenWhat
2 Jul 2025The first commit of okay, the platform.
7 Oct 2026okay-core begins: delimited continuations over rows of effects.
10 Oct 2026okay-kernel begins: one API for every language and platform.
12–14 Oct 2026The experiments beside okay-core: okay-free, okay-eff, okay-cont, okay-one. Each tried one way of putting effects and delimited control in one monad. okay-free kept the answer types in the effects' monad. okay-eff took them out and made k data. okay-cont put the rows inside the monad of shift0 and $. okay-one made the boundary between the framework and its kernel data. They are not published; what each found is recorded in okay-core's docs/one.md.
13–14 Oct 2026The decision: okay-core is one monad on one machine, k is data. okay-one's kernel becomes okay-core's package okay.one, and the okay platform moves onto it.
17–18 Oct 2026okay-simple: one interface for Scala 3 and 2.13. Released as 0.1.0 on 18 Oct; 0.1.1 on 4 Nov.
22–23 Oct 2026okay-direct: direct style on Java 25, with the Scala front ends. Released as 0.1.0.
23 Oct 2026okay-scala: Scala 3 alone, one CEK machine. Released as 0.1.0 the same day.
10 Nov 2026okay-effects, the repository: the kernel in Scala 3, Java 25 and Rust. Words that take their row from the declared type, and the row a handler leaves, are committed there, and in okay-scala later the same day.
11 Nov 2026okay-scala 0.1.1 is published with them.

Two lines are developed for Scala today: okay-scala, for applications in Scala 3, and okay-simple, the common interface for Scala 2.13 and 3. okay-effects is where the model is kept small and checked in three languages. okay-core is the kernel under the okay platform.
