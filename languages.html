Effects in other languages

The same idea, a program that asks operations and handlers that answer them, is implemented outside Scala in nine languages: Java, Kotlin, Rust, Go, Goose, Zig, TypeScript, Python and Lean. Each takes the form its language allows: a program as data run by a machine, direct style on the language's own continuations, coroutines or generators, a function compiled into a state machine, or a plain function over a typed context. Three things hold them to one meaning: one digest of a thousand random programs, test suites carried from one repository to another, and the okay wire, on which a program in one language is answered by handlers in another.

As of 11 November 2026: the state of the default branches. Every statement on this page was checked in the repositories; where a file says it, the file is named. The Scala implementations have a page of their own.

okay-direct also has front ends for Scala 3 and 2.13; they are on the Scala page. okay-rs is the earlier repository of okay-rust; its README says it has moved, and its history is in okay-rust. okay-effects is the reference model: one small kernel written three times, in Scala 3, Java 25 and Rust.

One rule holds across the family: a continuation resumed many times is a real value, a copy of frames, a cloned state machine or data; a body is never run again from its start. okay-python is the exception, and its guide says so: a generator cannot be copied, and every_path re-runs the body with the answers so far replayed, for a body that is pure apart from its effects (okay_effects/paths.py).

A program in each

Copied from each repository's own documentation or tests; the file is named.

okay-java (README.md)

interface Ask<L> { Eff<L, Integer> number(); }
interface Asked<L, A> { <M extends L> Eff<M, A> in(Ask<M> a); }   // a handler's body: a level of its own

static <L, A> Eff<L, A> asking(int n, Asked<L, A> body) {
  return Eff.handle(new Eff.Body<L, A, A>() {
    public <M extends L> Eff<M, A> in(Prompt<L, M, A> p) { return body.in(() -> p.shift0(k -> k.apply(n))); }
  }, Eff::pure);
}

okay-direct (README.md)

public sealed interface State<S> {
    record Get<S>() implements State<S>, Op<State<S>, S> {}
    record Put<S>(S value) implements State<S>, Op<State<S>, Void> {}
}

public void operation(State<S> op, Answer<State<S>> k) {
    switch (op) {
        case Get<S> get -> k.answer(get, state);
        case Put<S> put -> { state = put.value(); k.answer(put, null); }
    }
}

A program is plain Java that takes the capability: static int total(Effect<Prices> prices, Effect<Fail<String>> fail, List<String> cart), and performs inside a stream's lambda.

okay-effects, the Java kernel (README.md)

static Comp<Integer, Eff<State<Integer>, ?>> add(int x) {
  return State.<Integer>get().flatMap(s -> State.put(s + x).map(done -> s + x));
}
static Comp<Integer, Eff<State<Integer>, Eff<Choose, ?>>> p() {   // a state, and a choice under it
  return up(Choose.among(List.of(1, 2))).flatMap(x -> add(x));
}

run(Choose.all(State.run(0, p())));   // [Final[state=1, value=1], Final[state=2, value=2]]

fun interface Ask {

/** each ask answered with `n`, the rest resumed in the clause: a general handler in tail position */
suspend fun <A> answering(n: Int, body: suspend context(Ask) () -> A): A = handle { prompt ->
    context(Ask { prompt.shift { k -> k(n) } }) { body() }

okay-rust, a resumable function (README.md)

okay::effect! { pub enum Choose: Plain { Among(n: usize) -> usize = among; } }
okay::ops! { pub enum ChooseOps { Choose } }    // the operations it may stop at: an enum, `From` each effect

#[resumable(ChooseOps)]
fn pick(base: usize) -> usize {
    let a: usize = ask!(Choose::Among(3));      // a stop: the operation given to the handler
    let b: usize = ask!(Choose::Among(2));
    base + a * 10 + b
}

okay-effects, the Rust kernel (README.md)

fn p() -> impl Prog<i64, eff![State<i64>, Choose]> {
    Choose::among(vec![1, 2])
        .flat_map(|x| State::get().flat_map(move |s: i64| State::put(s + x).map(move |_| s + x)))

okay-goose (examples/handlers.okg)

effect Choose: many { among(n: i64) -> i64; }

okay-ts (README.md)

const Config = Reader("Config", of<number>())
const Counter = State("Counter", of<number>())

const program = eff(function* () {
  const n = yield* Config.ask()
  yield* Counter.modify((s) => s + n)

okay-python (tests/test_core.py)

@dataclass(frozen=True)
class Ask(Op[T], Generic[T]):
    pass

def reader(v: T, body: Callable[[Cap[Ask[T]]], Eff[A]]) -> Eff[A]:
    return (yield from answering(Ask, lambda _: v, body))

def prog(n: Cap[Ask[int]]) -> Eff[str]:
    def body(s: Cap[Ask[str]]) -> Eff[str]:
        return (yield from s.perform(Ask[str]())) * (yield from n.perform(Ask[int]()))

    return (yield from reader("ab", body))

self.assertEqual(run(reader(3, prog)), "ababab")

What a language allows

Each form follows from what the language has: a continuation that can be copied or not, types that can hold a set of effects or not, a compiler that can be extended or not.

Java

Java has no higher kinds and no type-level lists. Three answers are in the family. okay-direct keeps no row at all: a program is plain code, an effect is a sealed interface whose operations are records, a handler is an exhaustive switch, and the operation is the witness of its answer's type. What can be resumed depends on the JVM: HotSpot's continuation and a virtual thread are resumed once; Espresso can copy a suspended continuation's frames, so only EspressoEffects is a MultiEffects, and Choose.all does not compile against the other two. okay-java puts the handlers in force into a type variable: a handler's body is a generic method at a level M extends L that nothing outside can name, so a capability that leaves its handler does not compile (LeakTest). The price is in its README: a lambda cannot implement a generic method, so every handler's body is an anonymous class or a method reference. The Java kernel of okay-effects writes the row as a nested type with wildcards. It is positional: a program names its effects in the order of its handlers and is moved with up, under and fit; a handler takes its effect from the front of the row only.

Kotlin

Context parameters carry the effects: context(accounts: Accounts, fail: Fail<String>) on a suspend function is checked by the compiler. A handler that takes the rest of the body is a delimited continuation on the standard library's coroutines. A Kotlin continuation is resumed once; k.copy() copies the objects the compiler made of the suspend functions, up to the handler. That works on the JVM and in JavaScript; native code has no way to copy a frame, and the multi-shot tests are in a source set for the JVM and JS only. Handlers are chosen lexically: an operation goes to the handler whose capability it was given. The data style is the other answer: k is data on a machine, on every platform.

Rust

An async block is a state machine the compiler builds, generic over its context and monomorphized for the handlers it runs under; an operation answered in place is an inlined call. A future cannot be cloned, so the crate okay is one-shot by design. Where the rest must be taken many times, the rest has to be a value that is Clone: #[resumable] turns a function into an enum, one variant for each stop holding the variables in scope there, on stable Rust; with the feature coroutines, on nightly, the same comes from a coroutine that is cloned. Ownership does part of the typing: a state whose type changes from step to step is a token each step takes and gives back, and a context is a borrow that cannot outlive its handlers. In the Rust kernel of okay-effects a closure given to flat_map is FnOnce + Clone, a recursive program ends with .boxed(), and everything is of one thread.

Go

Go has no type-level lists, so a program's effects cannot be in its type; they are its capabilities, parameters and fields, as a Go program passes ctx. A handler answers only its own capability's operations, so two instances of one effect coexist. A program is a coroutine (iter.Pull); it cannot be copied, so a continuation is resumed once. Parallel branches run on goroutines, and a branch performs through a capability only after it is lent to it; its operations travel over a channel to the goroutine that owns the handler. Multi-shot is a separate package of programs as data.

Goose

Goose has no heap, no garbage collector, and function values only at compile time. So a set of effects is a context's type, a handler is an overload of the operations for that type, and an interceptor is a generic wrapper of a context. okay-goose is a translator, okgc, written in Goose: it reads Goose with four additions (effect, effects, A ! F + G, forward) and writes plain Goose on the same lines. A resumable fn is cut at each operation of a once or many effect into a state machine whose frame is one struct. A handler dropping the rest is return E from f, a jump.

Zig

Zig passes what a function needs as a value, as it does Allocator. A context is a tuple of handlers known at compile time, and an operation is a call the compiler inlines. A type is a call the compiler evaluates, so a row is Row(.{ F, G }) and a missing effect is a compile error with its own message. A guard that may refuse an operation makes that effect's operations answer an error union, so the program says try and the types show which operations may be refused. The machine takes steps in place of closures: each a function declared once and named. A union is copied by value, which is what a resumable program needs; the states are written by hand.

TypeScript

A union type is a row: an effect is a tag with a name, and run() is present only when the union is empty. A generator is the idiom, and a generator's state cannot be copied, so the third parameter of Eff<A, E, boolean> records whether a program may be resumed many times. Types are erased: the guarantees hold for code without casts, and at run time a generator resumed twice fails with ResumedTwice.

Python

Python has no rows. A program is a generator, typed by what each operation answers under mypy --strict; its effects are the capabilities it is given. The business code stays a generator under asyncio: run_async awaits at the top.

Lean

An effect is an inductive family indexed by the answer's type, so dependent pattern matching tells a handler that an operation is its own, with no cast. The monad laws and what each standard handler makes of its operations are theorems; there is no sorry. The limit is stated in the README: the theorems are about each interpreter's reference definition, and what runs is a second definition, unsafe and not proved equal to the first.

One meaning

One number is shared by four of the repositories on this page. Other suites are carried from repository to repository by hand. Some implementations are held to neither.

Working together

In one process, through okay-kernel's protocol. Between processes, on the okay wire.

In one process

okay-kernel is a protocol with its API in plain Java, no dependency: a program handed out steps to Done, Yield (an operation and its k, multi-shot), Failed or Cancelled. okay-java implements it with no wrapper: an Eff is the protocol's program, so its programs run under okay-core's handlers and okay-core's under its. okay-ts has the same steps, and okay-kernel's module js exports the protocol from Scala.js; test/kernel.test.ts runs programs both ways, and is skipped where that module is not built. okay-go, okay-python and the crate okay of okay-rust hand a program out to a host in the same shape (step, resume, fail, cancel), each in its own language.

The okay wire

The wire is the protocol of the okay platform: a far side (a worker) serves functions and programs by name, a host asks and answers the programs' operations under its own handlers, and may continue the same rest many times. Its specification is a transcript, okay-py/src/main/resources/okay/py/wire.txt. The platform has the host and its own far-side libraries for Python, R, TypeScript, Go, Rust and Haskell; Clojure, Frege and Java programs are walked inside the JVM (docs/foreign-languages.md).
